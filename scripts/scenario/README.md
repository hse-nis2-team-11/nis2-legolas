# Одна попытка с восстановлением ZooKeeper

[run.sh](run.sh) готовит стенд, а [Trial.java](Trial.java) управляет фазами одной попытки (подготовка кластера, запись, восстановление, проверка сохранности записей).

1. [Ensemble.java](Ensemble.java) поднимает узлы ZooKeeper. [Ready.java](Ready.java) читает корень и создаёт родительский путь для записей попытки.
2. Legolas разрешает инъекции на время работы писателя. [bounded.py](bounded.py) останавливает группу процессов писателя при тайм-ауте. В этом случае попытка продолжается.
3. Оркестратор закрывает окно инъекций и перезапускает узлы с прежними каталогами данных. Когда новый клиент успешно прочитает корень, запускается чекер.

При сборке применяются две поправки к Legolas. [pause-injections.patch](pause-injections.patch) позволяет закрыть окно инъекций перед восстановлением, [ensemble-size.patch](ensemble-size.patch) задаёт число узлов через конфигурацию.

## Как подключить писатель и чекер

Подготовь две исполняемые программы. Оркестратор вызывает каждую без аргументов и передаёт окружение:

| Переменная | Для чего нужна |
| --- | --- |
| `ZK_CONNECT` | Подключение к кластеру |
| `ZK_NAMESPACE` | Родительский путь для уникальных записей |
| `CLIENT_JOURNAL` | Писатель сохраняет сюда журнал, чекер читает его после восстановления |
| `TRIAL_DIR` | Каталог попытки для вердикта и других результатов |

Писатель сохраняет ID, путь и ожидаемые байты до отправки запроса, а ответ — сразу после получения. Дочерние клиенты остаются в группе процессов писателя. Чекер обрабатывает и неполный журнал: запрос без ответа имеет неизвестный исход. Вердикт сохраняется в `TRIAL_DIR`. Код выхода `0` означает завершённую проверку, в том числе при найденном нарушении. Ненулевой код означает ошибку выполнения, `124` — тайм-аут.

Формат журнала общий для писателя и чекера. Число клиентов, общий объём записей и сид задаёт писатель. Так новые варианты нагрузки подключаются через тот же интерфейс.

## Как запустить

Пример из корня репозитория для исполняемых файлов `hooks/write` и `hooks/check`:

```bash
docker build --network host -t nis2-legolas:scenario .
mkdir -p .local/results
docker run --rm --init --network none --hostname legolas --add-host legolas:127.0.0.1 \
  --user "$(id -u):$(id -g)" -v "$PWD/.local/results:/results" \
  -v "$PWD/hooks:/hooks:ro" --entrypoint bash nis2-legolas:scenario \
  scripts/scenario/run.sh /results/attempt-1 /hooks/write /hooks/check RoundRobinStateOp 30
```

Пять аргументов `run.sh` по порядку: новый каталог результатов, путь к писателю, путь к чекеру, политика (`None`, `Random`, `RoundRobinStateOp`) и тайм-аут в секундах для каждого вызова клиента. Пути задаются внутри контейнера. По умолчанию серверов три. Число можно изменить опцией Docker `-e ZK_SERVER_COUNT=5`.

В этом примере ход попытки виден в `.local/results/attempt-1/trials/0/phases.tsv`. Рядом лежат вывод каждой фазы, журналы узлов и события Legolas.
